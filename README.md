# StrayAssist Frontend

Website for **StrayAssist**, a stray animal rescue and adoption organization serving Batangas, Philippines. Visitors can browse rescued animals, apply to adopt, report a stray, volunteer, and pledge donations.

## Summary

| | |
|---|---|
| **Framework** | TanStack Start (React 19, SSR) on Vite 8 |
| **Routing** | TanStack Router, file-based (`src/routes`) |
| **Styling** | Tailwind CSS v4, shadcn/ui (new-york), Radix UI |
| **Forms** | react-hook-form helpers, Zod validation |
| **Data** | Static seed data in `src/data`; Spring Boot API proxied at `/api` |
| **Testing** | Vitest + Testing Library (jsdom) |
| **Tooling** | Bun, ESLint 9, Prettier, TypeScript (strict) |
| **Offline** | Production-only service worker with an offline fallback page |

## Getting Started

```bash
cd frontend
bun install
bun run dev
```

The dev server runs on Vite's default `http://localhost:5173`. Scripts, troubleshooting, and how-to guides are in [help.md](help.md). To run the full stack with the backend, see the root [help.md](../help.md).

## How It Works

**Routing and SSR.** `router.tsx` builds a fresh router and `QueryClient` per request so cached data never leaks between SSR requests. Page metadata (title, description, Open Graph) is set per route through `head()`.

**Layout and navigation.** `SiteLayout` wraps pages with the navbar and footer and scrolls to top on navigation. Menus are defined in `data/nav.ts`. `SmartLink` sends real paths through the router and leaves `#` placeholders as plain anchors.

**Forms.** Every form (adoption, rescue report, volunteer, donation) is validated in the browser with the Zod schemas in `lib/inquiry-schemas.ts`. Shared field components live in `components/site/form-fields.tsx`.

- Adopters must be 18 or older
- Photo uploads: JPEG, PNG, WebP, HEIC or HEIF, max 8 MB
- Adoption: about you, home, and verification steps (ID and home photos)
- Rescue report: animal, location (device GPS plus OpenStreetMap reverse lookup), and contact steps
- Nothing is submitted or stored yet

**Data.** Two Batangas shelters (Talisay, Tanauan) and the adoptable dogs and cats are defined as typed arrays in `data/rescues.ts`.

**Error handling.** `start.ts` and `server.ts` catch server errors and return a branded 500 page. `lib/error-capture.ts` preserves stack traces that h3 would otherwise swallow. The root route provides 404 and error boundaries.

**Offline support.** `public/sw.js` caches `offline.html` and serves it when a navigation fails. Registration runs in production builds only.

## Testing

Two suites, 21 tests:

- `app-routing.test.tsx` checks that every main URL matches a real route and not the not-found fallback
- `inquiry-rules.test.ts` checks the adopter rules (age, ID photo, home photos, landlord question)

## Conventions

- Prettier: 100 columns, semicolons, single quotes (including JSX), trailing commas
- Import alias: `@/*` maps to `src/*`
- Strict TypeScript, including `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes`
- Bun installs skip package versions published in the last 24 hours (`bunfig.toml`)

## Backend Integration

The Spring Boot API (Java 21, Gradle) lives in `../backend` and runs on `http://localhost:8080`. The frontend reaches it through the Vite dev proxy, so no CORS settings are needed.

- Call the API with absolute paths such as `fetch('/api/hello')`, never relative paths like `fetch('api/hello')`
- Make API calls from the browser, not from route loaders, since a relative URL fails during SSR
- `vite.config.ts` proxies `/api` to `VITE_PROXY_TARGET`: `http://backend:8080` in Docker, `http://localhost:8080` locally
- The proxy applies to the dev server only

Run commands and verification steps are in the root [help.md](../help.md).

## CI

Two workflows run only when their own folder changes, on pushes to `main` and on pull requests:

- `.github/workflows/ci.yaml` (frontend): install with a frozen lockfile, lint, type check, test, build, then upload `dist/` as an artifact
- `.github/workflows/backend-ci.yaml` (backend): `./gradlew build` on Java 21
